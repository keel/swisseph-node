# swisseph-node

Modern [Node.js](https://nodejs.org) binding for the [Swiss Ephemeris](https://www.astro.com/swisseph) — N-API (stable ABI), compiles the **upstream C sources unmodified**.

## Why another binding?

The classic `swisseph` npm package is NAN-based (must be rebuilt for every Node major), forks and patches the C code (hard to track upstream), and has been unmaintained for years. This package:

- **Zero modifications to upstream C code** — `binding.gyp` compiles the pristine sources directly, so updating to a new Swiss Ephemeris release is just dropping in the new `.c/.h` files and rebuilding.
- **N-API / node-addon-api** — one build works across Node major versions (≥16).
- **Clean layered API** — a faithful low-level mapping (`raw`) plus a high-level chart/synastry/sky API returning structured data ready for chart rendering.
- **No bundled data** — points at the Swiss Ephemeris files you already have (env var `SWISSEPH_EPHE_PATH`), falling back to the built-in Moshier ephemeris when none are found.

## Install / build

The package expects the Swiss Ephemeris sources next to it (default `../swisseph-master`). Override with:

```bash
npm install --sse_dir=/path/to/swisseph-sources
# or persistently:
npm config set sse_dir /path/to/swisseph-sources
```

Ephemeris data files (`semo_*.se1`, `sepl_*.se1`, `seas_*.se1`) are resolved at runtime from:

1. `setEphePath(path)` — explicit
2. `SWISSEPH_EPHE_PATH` env var
3. `../swisseph-master/ephe` relative to the package

Without data files it silently falls back to the Moshier analytical ephemeris (planets only, slightly lower precision — Chiron/asteroids unavailable).

## High-level API

```js
const swe = require('swisseph-node');

const chart = swe.computeChart({
  year: 2000, month: 1, day: 1, hour: 20, tz: 8,   // local time + UTC offset
  lat: 39.9042, lon: 116.4074,                      // Beijing
  houseSystem: 'P',                                 // Placidus
});
// chart.planets -> [{key:'sun', lon, sign:'capricorn', house, retrograde, speed, degreeInSign, ...}]
// chart.houses  -> {cusps[12], ascendant, midheaven, vertex, cuspsFormatted}
// chart.aspects -> [{a:'sun', b:'moon', aspect:{key:'square', orbDelta:1.2, ...}}]
// chart.balances-> {elements:{fire:3,...}, modes:{...}}

const syn = swe.computeSynastry(birthA, birthB);
// syn.crossAspects, syn.aHousesOfB, syn.bHousesOfA

const sky = swe.computeSky({ year: 2026, month: 10, day: 24, hour: 21, tz: 8, lat: 39.9, lon: 116.4 });
// sky.bodies -> [{key:'moon', azimuth, altitude, illumination}]
// sky.stars  -> bright-star catalog with horizontal coordinates
```

## Low-level API (`raw`)

One-to-one with the C API (`swephexp.h`): `version`, `setEphePath`, `julDay`, `revJul`,
`utcToJd`, `utcTimeZone`, `deltat`, `calcUt`, `houses`, `getPlanetName`, `ayanamsaUt`,
`azAlt`, `phenoUt`, `solEclipseWhenLoc`, `lunOccultWhenLoc`, `setTopo`, `setSidMode`, `close`.
